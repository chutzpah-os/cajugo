# Comprovantes e documentos privados servidos pelo nosso servidor

Comprovantes de Pix (spec 004) e, depois, documentos do vendedor (spec 008) ficam no Cloudinary como `type: authenticated`, sem URL pública, e só são abertos por uma rota nossa (`GET /api/v1/payments/{id}/receipt`) que confere a sessão e a posse a cada abertura e devolve o arquivo com `Cache-Control: private, no-store`; nenhuma URL do Cloudinary chega ao navegador. Descartamos entregar uma URL assinada ao navegador: a assinatura de entrega do Cloudinary não expira, a URL de download com prazo depende de recurso do plano, e o plano gratuito bloqueia a entrega de PDF. O custo é o tráfego da função para arquivos pequenos e abertos poucas vezes; em troca, o acesso é auditável, revogável na hora (é a sessão) e não muda na saída para a VPS. O arquivo recusado no envio (formato ou tamanho) é apagado do Cloudinary na mesma hora.

Prova no staging (004/T006): PNG e PDF enviados como `authenticated` não existem como públicos (URL pública 404), são lidos pelo servidor pela API de download assinada e apagados com `destroy`; a entrega de PDF por URL responde 401 no plano gratuito, sem afetar a nossa rota. A resposta do envio traz ao navegador do próprio lojista uma URL assinada que abre a imagem e não expira: o sistema nunca guarda nem repassa essa URL (só o `public_id`), e ela só chega a quem é dono do arquivo.
